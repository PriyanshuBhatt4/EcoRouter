# EcoRouteApp — Project Plan

EcoRouteApp is a **local-first, eco-friendly trip prototyper** built from the existing codebase. This plan was derived from what the app and API already do (conservative reading of the code), not from new product ambitions. Status checkboxes are updated as work completes.

## One-line product summary

A single user plans a walking or cycling trip: type a destination, get up to 3 candidate routes on a map, compare them (fastest / shortest / cleanest / optimal), optionally see a regional-model PM2.5 estimate, then track the actual trip with GPS and keep a local trip history.

## How to run (local demo)

Prerequisites: Node.js + npm, Python 3.13, and the **Expo Go** app (SDK 54) on a phone on the same Wi-Fi as the computer.

1. **Backend** (works with **no database and no Supabase configuration**):
   ```powershell
   cd backend
   .\ecorouter\Scripts\Activate.ps1
   pip install -r requirements.txt -r requirements-dev.txt
   .\ecorouter\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
 2. **Phone configuration**: `.env.local` (repo root) sets `EXPO_PUBLIC_API_BASE_URL` to the computer's LAN IP, e.g. `http://<your-computer-ip>:8000`. Update the IP if the computer's LAN IP changes (`ipconfig` shows it). For the Android emulator use `http://10.0.2.2:8000`; for an iOS simulator `http://localhost:8000`.
 3. **App**:
    ```powershell
    npm install
    npx expo start
    ```
    then scan the QR code with Expo Go.

`backend/alembic.ini` and `backend/alembic/env.py` contain in-progress user work and are **frozen** — not modified by us (hashes recorded in the milestone log below).

## Product requirements (conservative, derived from existing code)

- **R1 Routing**: free-text destination search from the device's current GPS position; server geocodes the destination, returns up to 3 candidate routes for `walking` / `cycling` (mode `driving` accepted by the API but not shown in the UI); failures map to friendly error messages (`NO_GEOCODING_RESULT`, `NO_ROUTE_FOUND`, `UPSTREAM_TIMEOUT`, `UPSTREAM_ERROR`, `INVALID_REQUEST`, network).
- **R2 Route comparison**: client-side preference ranking — fastest (duration, tie-break distance), shortest (distance, tie-break duration), cleanest (lowest PM2.5, only when the server says `can_compare_cleanest`), optimal (equal-weight normalized distance/time/PM2.5), manual default.
- **R3 Air-quality estimate**: regional-model (Open-Meteo/CAMS) PM2.5 mean per route, clearly labeled as NOT street-level; unavailable/indistinguishable states carry explicit caveats and never fake a "cleaner" choice.
- **R4 Trip tracking & history**: StartTrip/FinishTrip with foreground GPS distance accumulation; trips and lifetime totals persist locally via AsyncStorage across restarts.
- **R5 Local profile**: display name and weight (optional), stored on-device only.
- **R6 Optional cloud endpoints** (backend readiness only): `/me/profile`, `/me/trips`, `/me/stats` exist for an optional Supabase deployment; the app does not require an account and the demo is unaffected when DB/auth are unconfigured (endpoints answer with a clear `503` configuration error instead of crashing).
- **R7 Honest attribution/caveats**: routes come from public prototype services (OSM Nominatim, Valhalla public server, Open-Meteo) with no SLA; durations are provider estimates, not live traffic.

## Assumptions

- **A1** Educational/student prototype; single-user demo; not navigation, safety, or health product. PM2.5 is awareness, not medical advice.
- **A2** Demo target is a physical Android/iOS phone (or emulator) running Expo Go SDK 54; web is out of scope (map library/CORS limits).
- **A3** Local-first: AsyncStorage is the demo source of truth; cloud sync is out of scope for v1 until explicit product decisions (auth flow, merge policy).
- **A4** Public mapping/air-quality APIs are acceptable for the prototype; no caching/billing/keys needed for the demo.
- **A5** `driving` stays API-only (hidden in UI) — the eco focus is walking/cycling.
- **A6** Turn-by-turn maneuvers are out of scope; the dead maneuver UI is removed in app hardening.
- **A7** Environment files are machine-local (never committed); `.env.example` files document placeholders only.
- **A8** No database/Supabase credentials are available locally; `/me` is verified with tests/mocks and any live-Supabase verification is deferred to the user.
